# Cross-Lingual-BERT-Adaptation-English-Chinese-
## Project Overview

Although there are various well trained multilingual LLMs that are able to understand various languages, we wanted to see if these models could understand or decipher unknown or lost languages. To do this we decided to adapt a pretrained English only BERT masked language model to Spanish text by extending its tokenizer with Spanish subword units learned from a domain corpus. The central goal is to study how vocabulary expansion and training-set size affect masked language modeling quality on an unknown language.

The project uses a preprocessing pipeline to convert the raw Spanish corpus into clean training and validation files, and a Colab-friendly notebook to run controlled experiments. The main experiment grid compares three vocabulary expansion sizes, `{500, 1000, 2000}`, against three training-data budgets, `{50k, 100k, full}` articles. Each run keeps the training budget in optimization steps fixed so that model quality can be compared more fairly across conditions.

In practical terms, this repository supports three tasks:

1. Preprocess the raw Spanish corpus into `train.txt` and `valid.txt`.
2. Train an adapted masked language model with additional Spanish tokens.
3. Evaluate the model using loss, perplexity, tokenization efficiency, and qualitative masked-token predictions.

## Dataset

This project expects a Spanish text corpus distributed as multiple files named `spanishText_*`. The preprocessing script searches for those files inside a data directory and converts them into cleaned article-level text examples.

### Where to Download the Dataset

Download the raw Spanish corpus from this [Kaggle dataset](https://www.kaggle.com/datasets/rtatman/120-million-word-spanish-corpus). After downloading, unzip the dataset so that the extracted files named `spanishText_*` are placed inside the repository's `data/` directory.

Expected layout:

```text
data/
  spanishText_10000_15000
  spanishText_15000_20000
  spanishText_20000_25000
  ...
```

## How to Preprocess the Data

The preprocessing script:

- reads all files matching `spanishText_*`
- removes XML/HTML-like tags
- normalizes whitespace
- joins lines into article-level examples
- filters out very short articles
- creates a training split and a validation split

Run preprocessing with:

```powershell
python preprocess_spanish.py --data-dir data --output-dir processed --valid-fraction 0.02 --min-chars 120 --max-articles 2000000 --seed 1337
```

We mainly ran this script locally to save compute units on Google Colab, but you can run on Colab by running 
```
!python preprocess_spanish.py --data-dir data --output-dir processed --valid-fraction 0.02 --min-chars 120 --max-articles 2000000 --seed 1337
```


### Important Preprocessing Parameters

- `--data-dir`: Folder containing the raw `spanishText_*` files.
- `--output-dir`: Destination for `train.txt` and `valid.txt`.
- `--valid-fraction`: Fraction of articles reserved for validation.
- `--min-chars`: Minimum article length retained after cleaning.
- `--max-articles`: Maximum number of articles to write. Use a negative value for no cap.
- `--seed`: Random seed for deterministic splitting.

## How to Train the Model

Training is performed using mainly the `Spanish_learning_preprocessed.ipynb`. 

The notebook follows this procedure:

1. Install dependencies.
2. Upload `train.txt` and `valid.txt` into Colab.
3. Train a SentencePiece BPE tokenizer on the Spanish training data.
4. Select new Spanish tokens not already present in the base BERT vocabulary.
5. Extend `bert-base-uncased` with those new tokens.
6. Initialize new token embeddings from the average of their existing subword decomposition.
7. Fine-tune the model for masked language modeling.

The default run configuration in the notebook is:

```python
RUN_CONFIG = {
    "token_count": 500,
    "article_cap": 50000,
    "batch_size": 16,
    "learning_rate": 5e-5,
    "weight_decay": 0.01,
    "num_train_epochs": 1,
    "fixed_max_steps": 3000,
    "max_length": 128,
    "mlm_probability": 0.15,
    "warmup_ratio": 0.1,
    "eval_mask_examples": 40,
    "eval_text_samples": 500,
    "masked_accuracy_top_k": 5,
    "seed": 1337,
}
```

To train a different experiment, modify only the `RUN_CONFIG` cell in the notebook and rerun the training block. (i.e. incrementing "token_count" from 500, 1000, 2000 and "article_cap" by 50000, 100000, 300000/max).

### Aside on SentencePiece

SentencePiece is a data-driven subword tokenization algorithm that learns a vocabulary directly from raw text rather than relying on hand-crafted word boundaries or rules. In this project, we train a SentencePiece Bite-Pair Encoding (BPE) model on the Spanish training corpus so that it can discover frequent character sequences, word fragments, and complete words that are useful for representing Spanish efficiently. Although, this may not be the tokenizer BERT uses (WordPiece), this is the preferred method to be able to handlling raw, unknown text with special characters, so we chose to see if we could combine the methods.

## How to Evaluate the Model

The notebook evaluates each trained model using the following measures:

- `eval_loss`
- `perplexity`
- `token_ratio`
- `token_ratio_std`
- `masked_accuracy`

The notebook also produces qualitative masked-token predictions using a Hugging Face `fill-mask` pipeline.

Evaluation outputs are saved in Colab under:

- `/content/report_outputs/experiment_results.csv`
- `/content/report_outputs/qualitative_predictions.csv`

The trained model and tokenizer for a run are saved under:

- `/content/experiments/<experiment_name>/final`

## How to Reproduce the Results

To reproduce the main project workflow from scratch:

1. Download and unzip the raw Spanish corpus into `data/`.
2. Run `preprocess_spanish.py` to generate `processed/train.txt` and `processed/valid.txt`.
3. Open `Spanish_learning_preprocessed.ipynb` in Google Colab.
4. Run all notebook cells in order.
5. Upload the processed files when prompted.
6. Set `RUN_CONFIG` to the desired experiment.
7. Run the training cell.
8. Run the testing and results-table cells to generate evaluation artifacts.

To reproduce the full 3 x 3 experiment grid described in the notebook:

1. Run the notebook once for each token count in `{500, 1000, 2000}`.
2. For each token count, repeat the run for article caps corresponding to `50000`, `100000`, and `full`.
3. After each run, the notebook appends or updates the row in `experiment_results.csv`.
